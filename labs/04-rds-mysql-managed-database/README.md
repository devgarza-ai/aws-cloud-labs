# Lab 04 — Amazon RDS for MySQL

## Overview

This project provisions a small managed MySQL database, reviews the service-managed configuration, verifies readiness, and performs a deletion workflow that does not retain snapshots or automated backups.

## Project profile

| Item | Configuration |
| --- | --- |
| Region | US East (Ohio), `us-east-2` |
| Provisioning method | Easy create |
| Engine | MySQL Community |
| DB instance class | `db.t4g.micro` |
| Storage | 20 GiB |
| Network | Default VPC; single Availability Zone |
| Public access | Disabled |
| Multi-AZ | Disabled |
| IAM database authentication | Disabled |
| Credentials | Automatically generated self-managed password; not retained in the repository |

## Implementation

1. Created the MySQL DB instance with the small-instance preset.
2. Reviewed the compute, storage, network, authentication, monitoring, and backup settings generated by Easy create.
3. Waited for the database state to become `Available`.
4. Confirmed that the monitoring view reported zero client connections.

## Validation scope

The project verified successful provisioning and service readiness in the RDS console. It did not claim an application-level MySQL connection or query test.

## Lifecycle and cleanup

The deletion workflow intentionally disabled both **Create final snapshot** and **Retain automated backups**. After deleting the DB instance, the following related resources were checked independently:

| Resource | Final state |
| --- | --- |
| DB instance | Deleted |
| Manual snapshots | None retained |
| Current and retained automated backups | None retained |
| DB subnet group created for the lab | Deleted |
| RDS monitoring role created for the lab | Deleted |

## Key takeaways

- RDS manages database infrastructure, but connectivity, credentials, backups, and deletion behavior remain explicit design decisions.
- An `Available` state confirms service readiness, not application connectivity.
- Database deletion is incomplete from a cost and data-lifecycle perspective until snapshots, retained backups, subnet groups, and auxiliary roles are reviewed.
